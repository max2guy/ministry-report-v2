# Auth Entry Screen Design

## Summary

사역보고서 앱 접속 시 곧바로 보고서 편집 화면으로 진입하지 않고, 먼저 로그인 전용 진입 화면을 보여준다. 이 화면은 단일 인증 화면 안에서 `로그인`, `계정 생성`, `계정 찾기` 3개 탭을 전환하는 방식으로 구성한다.

샘플 화면의 인상은 참고하되, 현재 앱의 내부 업무용 성격에 맞게 과한 장식 없이 차분한 중앙 정렬 인증 레이아웃으로 재구성한다.

## Goals

- 앱 첫 진입 시 인증 흐름을 분리해 구조를 명확히 한다.
- 기존 계정 생성, 로그인, 임시 비밀번호 변경 흐름을 유지한다.
- `계정 찾기` 흐름을 추가해 이메일 일부 확인과 관리자 복구 안내를 제공한다.
- 로그인 전에는 보고서 편집기, 뷰어, 저장 목록이 노출되지 않게 한다.

## Non-Goals

- 외부 메일 발송 기반 비밀번호 재설정 구현
- 다중 페이지 라우팅 도입
- 관리자 전용 별도 인증 앱 분리
- 소셜 로그인 또는 SSO

## User Flow

### 1. 로그인 전 진입

- 사용자가 앱에 접속하면 인증 게이트 화면이 먼저 보인다.
- 기본 선택 탭은 `로그인`이다.
- 기존에 로그인된 계정이 로컬에 유지되어 있으면 게이트를 건너뛰고 앱 본문으로 진입한다.

### 2. 로그인

- 입력값: 이메일, 비밀번호
- 성공 시 현재 계정이 활성화되고 기존 앱 본문으로 진입한다.
- `mustChangePassword` 상태 계정도 로그인 가능하다.
- 해당 계정은 앱 진입 후 기존과 동일하게 비밀번호 변경을 요구받는다.

### 3. 계정 생성

- 입력값: 이름, 이메일, 비밀번호
- 성공 시 계정이 생성되고 자동 로그인 상태로 앱 본문에 진입한다.
- 기존 중복 이메일, 잘못된 이메일 형식, 짧은 비밀번호 검증은 그대로 유지한다.

### 4. 계정 찾기

- 입력값: 이름, 이메일
- 입력한 이름과 이메일이 기존 계정과 일치하면 이메일 일부를 마스킹한 결과를 보여준다.
  - 예: `ki***@gmail.com`
- 비밀번호 분실 사용자는 같은 화면에서 `비밀번호는 관리자 복구가 필요합니다.` 안내를 본다.
- 여기서 직접 비밀번호를 변경하거나 이메일을 발송하지 않는다.

## Information Architecture

### Logged-out Surface

- 전체 앱을 덮는 인증 전용 화면
- 구성 요소:
  - 앱 이름/짧은 설명
  - 탭 전환 바
  - 현재 탭의 폼
  - 상태 메시지 / 오류 메시지
  - 필요 시 관리자 복구 안내 문구

### Logged-in Surface

- 현재 `App`의 기존 편집/뷰어/히스토리 구조 유지
- 로그인 이후에만 렌더링

## Component Design

### `AuthGate`

- 로그인 전용 진입 화면 컨테이너
- 탭 상태를 관리한다.
- `로그인`, `계정 생성`, `계정 찾기` 폼을 한 곳에서 전환한다.

### `AccountLookupForm`

- 이름 + 이메일 입력
- 계정 조회 성공 시 마스킹된 이메일 표시
- 실패 시 `일치하는 계정을 찾지 못했습니다.` 메시지 표시
- 성공 여부와 관계없이 비밀번호 재설정은 관리자 복구 안내로 연결

### Existing Forms Reused

- `SignInForm`
- `SignUpForm`
- `PasswordChangePanel`

기존 인증 로직과 검증 규칙은 유지하고, 배치만 로그인 게이트 안으로 이동한다.

## Data and State

### Existing State Kept

- 현재 계정 선택 및 로그인 상태
- 계정 생성/로그인/임시 비밀번호 변경 로직
- `CURRENT_ACCOUNT_ID_KEY` 기반 현재 계정 유지

### New State

- 인증 게이트 활성 탭 상태
- 계정 찾기 결과 메시지

## Account Lookup Rules

- 이메일 비교는 기존과 동일하게 정규화 후 비교한다.
- 이름 비교는 `trim()` 기준으로 정확히 일치해야 한다.
- 결과 표시는 전체 이메일이 아니라 일부 마스킹 값만 보여준다.
- 실패 시 계정 존재 여부를 과하게 노출하지 않는 단일 실패 메시지를 사용한다.

## Styling Direction

- 샘플처럼 로그인 전용 첫 화면의 분리감은 유지한다.
- 다만 현재 앱의 업무용 톤에 맞춰 다음 원칙을 적용한다:
  - 어두운 청록/남색 계열 배경
  - 중앙 정렬 인증 패널
  - 과한 일러스트 없음
  - 버튼과 입력은 현재 앱의 시각 언어를 확장한 수준으로 맞춤
  - 모바일과 데스크톱 모두 한 화면에서 무리 없이 사용 가능

## Testing

- 로그인 전에는 편집기/뷰어가 보이지 않는지 검증
- 로그인 성공 시 앱 본문으로 진입하는지 검증
- 계정 생성 성공 시 자동 로그인되는지 검증
- 계정 찾기 성공 시 마스킹 이메일이 표시되는지 검증
- 계정 찾기 실패 시 단일 오류 메시지가 보이는지 검증
- 기존 임시 비밀번호 로그인 및 비밀번호 변경 흐름이 계속 동작하는지 회귀 검증

## File Impact

- Modify: `src/App.tsx`
  - 로그인 전/후 렌더링 게이트 추가
- Modify: `src/features/auth/ReporterAccountPanel.tsx`
  - 앱 내부 계정 패널 역할 축소 또는 로그인 후 정보 패널 역할로 조정
- Create: `src/features/auth/AuthGate.tsx`
  - 인증 진입 화면
- Create: `src/features/auth/AccountLookupForm.tsx`
  - 계정 찾기 폼
- Modify: `src/auth/internalAuthStore.ts`
  - 이름+이메일 일치 계정 조회 함수 추가
- Modify: `src/styles.css`
  - 인증 게이트 전용 스타일 추가
- Modify: `tests/smoke/report-v2.spec.ts`
  - 로그인 게이트 진입과 계정 찾기 플로우 추가

## Open Decisions Resolved

- 인증 화면은 별도 3페이지가 아니라 한 화면 안 탭 전환으로 구성한다.
- 계정 찾기는 이메일 일부 확인 + 관리자 복구 안내 조합으로 간다.
- 비밀번호 재설정 메일 발송은 도입하지 않는다.
